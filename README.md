# Лабораторная работа: шифрование данных пользовательских папок

## 1. Постановка задачи

Необходимо реализовать консольное приложение для защиты пользовательских файлов, расположенных в выбранной папке и её подпапках. Защита выполняется путём шифрования содержимого файлов. Для получения доступа к данным пользователь выполняет обратную операцию — дешифрование.

Входные данные программы:

- режим работы: `encrypt` или `decrypt`;
- путь к папке;
- пароль.

## 2. Предлагаемое решение

### 2.1 Общая идея

Программа принимает папку и пароль, рекурсивно обходит дерево каталогов с помощью `std::filesystem::recursive_directory_iterator` и для каждого обычного файла вызывает Singleton-класс `FileCryptor`.

Для шифрования используется схема:

```text
PBKDF2-HMAC-SHA256(password, salt, 210000 iterations) -> 256-bit key
AES-256-GCM(key, IV) -> ciphertext + authentication tag
```

Для каждого файла генерируются новые случайные значения:

- `salt` — 16 байт;
- `IV` — 12 байт;
- `tag` — 16 байт.

Формат зашифрованного файла:

```text
RSZIENC1 | version | saltSize | ivSize | tagSize | iterations | salt | iv | ciphertext | tag
```

`RSZIENC1` — magic-заголовок. Он позволяет определить, был ли файл уже зашифрован программой. Это защищает от повторного шифрования одного и того же файла.

Используется AES-GCM, поэтому программа не просто шифрует данные, но и проверяет их целостность (AEAD). Если пароль неверный или файл был повреждён, дешифрование завершается ошибкой аутентификации, а исходный зашифрованный файл остаётся без изменений.

### 2.2 Используемые сущности

#### `main.cpp`

Отвечает за:

- разбор CLI-аргументов;
- проверку режима `encrypt`/`decrypt`;
- запуск `DirectoryProcessor`;
- вывод итоговой статистики;
- верхнеуровневый `try/catch` для защиты от необработанных исключений.

#### `DirectoryProcessor`

Отвечает за:

- рекурсивный обход выбранной папки;
- пропуск временных файлов программы;
- обработку обычных файлов;
- обработку символических ссылок на файлы;
- защиту от повторной обработки одного и того же файла через разные пути;
- подсчёт статистики: обработано, пропущено, ошибок, использованных ссылок.

#### `FileCryptor`

Основной класс шифрования и дешифрования. Реализован как Singleton.

Отвечает за:

- проверку magic-заголовка;
- генерацию `salt` и `IV`;
- получение ключа через PBKDF2-HMAC-SHA256;
- потоковое шифрование AES-256-GCM;
- потоковое дешифрование AES-256-GCM;
- проверку authentication tag;
- безопасную замену файла через временный файл и backup;
- RAII-управление OpenSSL-контекстом.

#### `CryptoException`

Исключение для ошибок криптографических операций, файлового ввода-вывода и некорректного формата данных.

#### `ProcessingResult`

Структура со статистикой выполнения.

### 2.4 Паттерн Singleton

`FileCryptor` реализован как Singleton.

Назначение паттерна Singleton — гарантировать, что у класса существует только один объект, и предоставить глобальную точку доступа к этому объекту.

В данной работе Singleton применён к классу `FileCryptor`, потому что:

- логически в программе достаточно одного криптографического сервиса;
- класс не хранит состояние конкретного файла между вызовами;
- создание объекта скрыто от внешнего кода;
- копирование и перемещение запрещены.

Реализация:

```cpp
FileCryptor& FileCryptor::instance()
{
    static FileCryptor instance;
    return instance;
}
```

В C++11 и новее инициализация локального `static` объекта потокобезопасна.

### 2.5 Используемые технологии

#### `std::filesystem`

`std::filesystem` используется для:

- проверки существования пути;
- проверки типа объекта: файл, каталог, symbolic link;
- рекурсивного обхода директорий;
- получения canonical/weakly_canonical путей;
- замены файлов через `rename`;
- восстановления прав доступа и времени изменения файла.

#### OpenSSL EVP API

OpenSSL используется для криптографических операций:

- `RAND_bytes` — криптографически стойкая генерация `salt`, `IV` и суффиксов временных файлов;
- `PKCS5_PBKDF2_HMAC` — получение ключа из пароля;
- `EVP_aes_256_gcm` — AES-256 в режиме GCM;
- `EVP_EncryptUpdate`/`EVP_DecryptUpdate` — потоковая обработка данных;
- `EVP_CIPHER_CTX_ctrl` — получение и установка GCM authentication tag;
- `OPENSSL_cleanse` — очистка копии пароля и ключа в памяти.

#### AES-256-GCM

AES-256-GCM решает две задачи:

1. конфиденциальность — содержимое файла становится нечитаемым без ключа;
2. контроль целостности и подлинности — при неверном пароле или изменении файла проверка tag завершается ошибкой.

В программе заголовок файла передаётся как AAD — authenticated additional data. Это значит, что параметры шифрования также участвуют в проверке tag.

#### PBKDF2-HMAC-SHA256

Пользователь вводит пароль, а AES требует бинарный ключ фиксированной длины. Поэтому пароль преобразуется в 256-битный ключ через PBKDF2-HMAC-SHA256.

Используются:

- случайный `salt` для каждого файла;
- 210000 итераций;
- итоговый ключ 32 байта.

Salt не является секретом и хранится в заголовке файла.

#### RAII

В коде нет владения ресурсами через `new`/`delete`. OpenSSL-контекст обёрнут в `std::unique_ptr` с пользовательским deleter:

```cpp
using EvpCipherContextPtr = std::unique_ptr<EVP_CIPHER_CTX, EvpCipherContextDeleter>;
```

Это защищает от утечек памяти при исключениях.

### 2.6 Подходы безопасной разработки

В реализации применены следующие меры:

- потоковая обработка файлов блоками по 64 KiB, без загрузки файла целиком в память;
- временный файл создаётся рядом с исходным файлом;
- исходный файл заменяется только после успешного завершения криптографической операции;
- при ошибке временный файл удаляется;
- при неверном пароле исходный зашифрованный файл не изменяется;
- используется AES-GCM с authentication tag;
- каждый файл получает отдельный `salt` и `IV`;
- повторное шифрование уже зашифрованных файлов пропускается;
- symbolic link не перезаписывается;
- symbolic link на файл обрабатывает целевой файл только если он находится внутри выбранной папки;
- symbolic link на каталог не обходится;
- один и тот же canonical path не обрабатывается дважды;
- исключения перехватываются на уровне обработки файла и на уровне `main`;
- пароль пустой строкой запрещён;
- временные и backup-файлы программы пропускаются при обходе;
- использование RAII-подхода при работе с памятью;
- компиляция возможна с AddressSanitizer/UndefinedBehaviorSanitizer.

Ограничение: пароль передаётся CLI-аргументом, поэтому он может быть виден в истории shell или списке процессов.

## 3. Инструкция пользователя

### 3.1 Зависимости

Debian/Ubuntu:

```bash
sudo apt update
sudo apt install build-essential cmake libssl-dev
```

Windows:

- установить CMake;
- установить компилятор MSVC или MinGW;
- установить OpenSSL development package;
- передать CMake путь к OpenSSL, если он не найден автоматически.

### 3.2 Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Сборка с санитайзерами на Linux:

```bash
cmake -S . -B build_asan -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build_asan
```

### 3.3 Запуск

Шифрование:

```bash
./build/folder_protector encrypt ./data "StrongPassword123!"
```

Дешифрование:

```bash
./build/folder_protector decrypt ./data "StrongPassword123!"
```

Формат CLI:

```text
folder_protector encrypt <directory_path> <password>
folder_protector decrypt <directory_path> <password>
```

### 3.4 Пример работы

Исходная структура:

```text
data/
├── a.txt
├── empty.bin
└── subdir/
    ├── b.txt
    └── random.bin
```

Команда:

```bash
./build/folder_protector encrypt ./data "StrongPassword123!"
```

Пример вывода:

```text
[ENCRYPTED] ./data/a.txt
[ENCRYPTED] ./data/empty.bin
[ENCRYPTED] ./data/subdir/b.txt
[ENCRYPTED] ./data/subdir/random.bin

Summary:
  encrypted files: 4
  decrypted files: 0
  skipped files:   0
  failed files:    0
  symlinks used:   0
```

После шифрования содержимое файлов становится нечитаемым. Повторный запуск `encrypt` пропустит уже зашифрованные файлы.

Для восстановления:

```bash
./build/folder_protector decrypt ./data "StrongPassword123!"
```

## 4. Тестирование

Для автоматической проверки подготовлен скрипт:

```bash
./scripts/run_tests.sh
```

Скрипт выполняет:

- Release-сборку;
- создание тестового дерева файлов;
- создание текстового файла;
- создание вложенного текстового файла;
- создание пустого файла;
- создание бинарного файла;
- создание внутренней symbolic link на файл;
- создание внешней symbolic link на файл;
- расчёт SHA-256 исходных файлов;
- шифрование;
- проверку magic-заголовка;
- проверку, что исходный текст не виден в зашифрованном файле;
- повторное шифрование;
- попытку дешифрования неверным паролем;
- проверку, что неверный пароль не изменил файлы;
- корректное дешифрование;
- сравнение SHA-256 после дешифрования с исходными SHA-256;
- проверку, что внешний symlink target не изменён;
- сборку с ASan/UBSan;
- smoke-test с санитайзерами;
- Valgrind-проверку, если Valgrind установлен.

### 4.1 Тест-кейсы

| ID | Входные данные / действие | Ожидаемая реакция программы |
|---|---|---|
| case1 | `encrypt ./data "StrongPassword123!"`, в папке есть обычные файлы | Все обычные файлы шифруются, программа выводит `[ENCRYPTED]`, код возврата `0` |
| case2 | `decrypt ./data "StrongPassword123!"` после case1 | Все файлы восстанавливаются, SHA-256 совпадает с исходным, код возврата `0` |
| case3 | Повторный запуск `encrypt` на уже зашифрованной папке | Файлы с magic `RSZIENC1` пропускаются, повторного шифрования нет |
| case4 | `decrypt` с неверным паролем | Проверка GCM tag завершается ошибкой, файлы не заменяются, код возврата не `0` |
| case5 | В папке есть пустой файл | Пустой файл шифруется и дешифруется, после восстановления остаётся пустым |
| case6 | В папке есть бинарный файл | Бинарный файл шифруется и дешифруется, SHA-256 совпадает |
| case7 | В папке есть вложенная подпапка | Файлы во вложенной подпапке обрабатываются рекурсивно |
| case8 | В папке есть symbolic link на файл внутри выбранной папки | Ссылка не перезаписывается, целевой файл обрабатывается один раз |
| case9 | В папке есть symbolic link на файл вне выбранной папки | Целевой файл не изменяется, ссылка пропускается безопасным default-поведением |
| case10 | В папке есть symbolic link на каталог | Ссылка на каталог не обходится, чтобы избежать циклов |
| case11 | Путь к папке не существует | Программа выводит ошибку и завершает работу с кодом не `0` |
| case12 | Передан пустой пароль | Программа отказывается выполнять операцию и возвращает ошибку |
| case13 | Нет прав на чтение/запись отдельного файла | Ошибка фиксируется для конкретного файла, остальные файлы продолжают обрабатываться |
| case14 | Повреждён заголовок или tag зашифрованного файла | Дешифрование завершается ошибкой, исходный файл не заменяется |
| case15 | Запуск без нужных аргументов | Выводится инструкция использования, код возврата не `0` |
| case16 | В папке находится исполняемый файл шифровальщика | Шифруются все файлы в папке, кроме исполняемого файла шифровальщика |

### 4.2 Проверка памяти

Рекомендуемые команды:

```bash
cmake -S . -B build_asan -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build_asan
ASAN_OPTIONS=detect_leaks=1 ./build_asan/folder_protector encrypt ./data "StrongPassword123!"
ASAN_OPTIONS=detect_leaks=1 ./build_asan/folder_protector decrypt ./data "StrongPassword123!"
```

Valgrind:

```bash
valgrind --leak-check=full --show-leak-kinds=all ./build/folder_protector encrypt ./data "StrongPassword123!"
valgrind --leak-check=full --show-leak-kinds=all ./build/folder_protector decrypt ./data "StrongPassword123!"
```
